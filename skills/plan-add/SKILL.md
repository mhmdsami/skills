# Capture work

Read `plan-spec` before saving files. Locate its SKILL.md beside this skill in the source checkout or among installed skills; if unavailable, request that dependency before writing.

1. Resolve the documentation root and owning workstream. Search that workstream's `plans/*/plan.md` by topic, not filename alone. If ownership is unclear, search across workstreams. Reuse a matching plan rather than creating a duplicate; do not reopen completed work unless the user intends new work.
2. Capture the problem, supplied links/context, and known constraints in a concise draft at the specified plan path. Do only the brief lookup needed to avoid duplication and misleading context. Distinguish supplied claims from verified facts.
3. Leave unanswered decisions in Open questions. Do not invoke a mandatory interview, invent phases, create an execution session, or imply approval.
4. Return the saved path and a one-sentence description. Proceed to plan-write only if the user also requested investigation or design.

An existing active plan keeps its status and history when new context is added. Explicitly new work following a completed plan gets its own linked draft.
