# Prepare work

Read plan-spec from sibling or installed skills. Ask for it if missing.

1. Resolve the owner and find existing work. Read its plan, ledger, and latest handoff before revising it; preserve settled scope and history.
2. Inspect code and evidence. Separate facts, hypotheses, and decisions. Verify bugs/findings before prescribing fixes; an investigation may conclude no change is needed.
3. Use grilling for unresolved user decisions and domain-modeling when terminology or architecture needs work. Look up facts yourself. Disclose missing dependencies; ask before substituting for a needed skill.
4. Record bounded phases, repository dependencies, acceptance checks, completion, and open questions using the shared format.
5. Present the plan. With settled scope and existing implementation authorization, continue through plan-execute. Otherwise keep proposed implementation draft. No-change investigations finish according to their completion criterion without requesting implementation approval.

Planning-only requests allow planning documents and explicitly authorized supporting material. Record material additions to active scope separately from prior authorization.
