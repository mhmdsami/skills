# Review the workflow

Read plan-spec from sibling or installed skills. Ask for it if missing.

1. Bound the review by workstream/period. Read plans, outcomes, execution evidence, and available exchanges. Separate user decisions from generated suggestions; state missing sources.
2. Find recurring misunderstandings, rejected findings resurfacing, validation failures, approval loops, or transfer problems. Compare promised and delivered outcomes. One task-specific exception is not a permanent preference.
3. Propose an edit to the owning skill: current wording, replacement, supporting examples, expected effect. Keep Git, voice, review, and grilling behavior in their owners; remove conflicting instructions before adding overrides.
4. Apply only authorized edits, using skill-creator when available. Otherwise leave proposals unapplied. Store requested retrospectives under workstream learnings/ or audits/, linked to source evidence.

Report when no edit is warranted; incomplete evidence narrows conclusions.
